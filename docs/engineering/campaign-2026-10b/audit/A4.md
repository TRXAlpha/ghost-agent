## Summary

- Status counts (33 rows across R04+R14): LIVE 3; PARTIAL 25; TEST-ONLY 0 (one unreachable-by-entry-point method block noted in R14 rows); STUB 0; MISSING 4; BLOCKED-EXTERNAL 1.
- Top 5 highest-value gaps for the owner:
  1. `ghost control-plane` crashes with AttributeError (cli.py:2877, GhostSDK.snapshot_json missing) — the primary structured control-plane command is broken on master; one-line fix + test.
  2. No single enforced authorization path: CapabilityKernel+ApprovalStore (orchestrator) and GrantStore+authorize_call (bridge) are parallel systems; the worker never consults grants/approvals when dispatching jobs.
  3. No Suggest/Build/Operate/Improve mode system anywhere — R04's core configurability is absent, not partial.
  4. Control-plane visibility is read-only and narrow: goal_tree/opportunity_pipeline/resource_usage/integration_health/notification_preferences exist in GhostSDK but have no CLI/API caller; API exposes only snapshot/goals/observations; no data export command.
  5. Revocation/EmergencyStop do not cancel queued work or close sessions, and no emergency-stop latency is measured per backend (R04 explicit requirement).
- External blockers: none for A4 engineering; the one BLOCKED-EXTERNAL row (servo approval-free motion) requires real device hardware/firmware, owned by area A8. Note: 2 tests in tests/test_openjarvis_authority.py fail on this machine's Python 3.14.2 because the OpenJarvis bridge gate requires Python 3.11–3.13 (runtime.py:22-24, `require_upstream`); the authority logic itself is covered by the other 12 passing tests in that file.
