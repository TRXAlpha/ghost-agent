closes that gap. It is not a replacement for OpenJarvis.

## E6-2: inference profiles

`ghost_agent/inference_profiles.py`:

```python
@dataclass
class InferenceProfile:
    name: str                 # ^[a-z0-9][a-z0-9_-]{0,30}$
    backend: str              # "legacy" (Ollama) | "openai" | "openjarvis"
    model: str
    url: str = ""             # required for openai/openjarvis
    research_model: str = ""  # default: same as model
    key_env: str = ""         # NAME of an env var holding the key (never the key)
    key_file: str = ""        # path to a KEY=VALUE env file; read at apply time
    key_name: str = ""        # variable name inside key_file
    timeout_s: int = 180
```

- The store is `<root>/.ghost/profiles.json` `{"version": 1, "active": str|null, "profiles": [...]}`, via
  `atomic_json`. If `GHOST_PROFILES_FILE` is set, use that path instead (so one profile file can serve
  several Ghost homes).
- `apply(profile) -> None` sets **process** env only:
  - `legacy` → `GHOST_INFERENCE_BACKEND=legacy`.
  - `openai` → `GHOST_INFERENCE_BACKEND=openai`, `GHOST_OPENAI_URL=url`, and `GHOST_OPENAI_API_KEY` from
    `key_env` (`os.environ[key_env]`) or `key_file`/`key_name` (parse lines `NAME=VALUE`, strip quotes).
  - `openjarvis` → the existing `GHOST_OPENJARVIS_*` variables plus `GHOST_ALLOW_REMOTE_INFERENCE=1` for
    non-local URLs.
  - It also sets `GHOST_OLLAMA_TIMEOUT=timeout_s` and `GHOST_MODEL=model` if those are unset.
  - A missing key source → `ProfileError("key not found for profile <name>")`, without the value.
- In `cli.py::main()`, before command dispatch: if `GHOST_INFERENCE_BACKEND` is **not** already set in the
  environment and an active profile exists in `Path.cwd()`'s store (or `GHOST_PROFILES_FILE`), call `apply`.
  On `ProfileError`, print one warning line and continue. Explicit env vars always win.
- CLI: `ghost profile add <name> --backend B --model M [--url U] [--key-env V | --key-file F --key-name N] [--research-model R] [--timeout S]`,
  `ghost profile list` (never shows keys; shows the key *source* kind), `use <name>`, `show <name>`,
  `remove <name>`, `test <name>` (one tiny chat "Reply OK" through the profile; prints ok/err and the
  latency, never the key).

**Tests:** round trip; name validation; apply sets env from key_env and key_file (tmp env file); a missing
key raises without leaking the value; main() applies the active profile only when the env is unset; list
output contains no key value; `test` with patched chat.

## E6-3: goals CLI and `ghost home init`

- `ghost goal add "title" [--kind outcome|learning|project|personal] [--priority 0-100] [--deadline YYYY-MM-DD]`,
  `ghost goal list [--all]`, and `ghost goal done <id>`, using the existing `GoalStore` (kernel.py: read its
  `create`/`active` and status methods; reuse them; add no new store). If GoalStore has no way to mark
  done, add a minimal `complete(goal_id)` method in kernel.py; this one kernel.py change is allowed.
- `ghost home init <dir> [--force]` creates the directory (refuses a non-empty dir unless `--force`) with:
  `README.md` (what a Ghost home is, the 6 commands to start), `context/` containing `about-me.md`
  (a template with headings: Goals, Projects, Devices, Learning, Preferences, Quiet hours), and
  `.ghost/policy.json` with the defaults (via `PolicyStore`). It prints the next steps: add goals,
  `ghost profile add`, `ghost policy set idle_work on`, `ghost daemon run`. It never starts anything.

**Tests:** goal add/list/done; deadline parse; home init creates the files and refuses non-empty;
policy defaults written.
