## E4-1: skill store and retrieval (review: 2)

New module `ghost_agent/skills.py`:

```python
SKILL_STATUSES = ("candidate", "active", "retired")

@dataclass
class Skill:
    skill_id: str              # "sk_" + 12 hex
    title: str                 # <= 80 chars
    when_to_use: str           # <= 300 chars, describes the task pattern
    steps: list[str]           # 1..6 items, each <= 200 chars
    pitfalls: list[str]        # 0..4 items, each <= 200 chars
    source_job_id: str = ""
    status: str = "candidate"
    uses: int = 0
    successes: int = 0
    created_at: float = field(default_factory=time.time)
    updated_at: float = field(default_factory=time.time)
    retired_reason: str = ""

class SkillError(ValueError): ...

class SkillLibrary:
    def __init__(self, root: Path)                  # file: <root>/.ghost/skills/skills.json
    def add(self, skill: Skill) -> Skill            # validates all limits; duplicate title (case-insensitive) -> SkillError
    def get(self, skill_id: str) -> Optional[Skill]
    def list(self, status: Optional[str] = None) -> list[Skill]
    def retrieve(self, goal: str, k: int = 2) -> list[Skill]
    def record_outcome(self, skill_ids: list[str], success: bool) -> None
    def record_baseline(self, success: bool) -> None   # a job that used NO skills
    def stats(self) -> dict
    def retire(self, skill_id: str, reason: str) -> Skill
    def consolidate(self) -> list[tuple[str, str]]     # returns (kept_id, merged_id) pairs
```

- **Storage:** `{"version": 1, "skills": [...], "baseline": {"uses": int, "successes": int}}`,
  written with `atomic_json` under `exclusive_lock(<file>.lock)`. A corrupt file raises `SkillError`;
  never overwrite it silently.
- **Tokens:** lowercase words of length ≥ 3, minus a small fixed stopword set.
  Write it as module function `_tokens(text) -> set[str]`.
- **`retrieve`:** among non-retired skills, score = Jaccard(goal tokens, title+when_to_use tokens).
  Keep scores ≥ `RETRIEVE_MIN_SCORE = 0.12`, sort by (score desc, utility desc), return the top `k`
  (0 ≤ k ≤ 5; anything else raises `SkillError`). `retrieve` never mutates the store.
- **Utility:** `(successes + 1) / (uses + 2)`. The prior is `(baseline.successes + 1) / (baseline.uses + 2)`.
- **`record_outcome`**, for each id (unknown ids ignored): `uses += 1`; on success `successes += 1`. Then:
  - `candidate` → `active` when `uses >= 2` and `utility >= prior`.
  - `candidate`/`active` → `retired` with `retired_reason = "utility <u> below prior <p>"` when
    `uses >= 4` and `utility < prior - 0.15`.
- **`consolidate`** (deterministic, no model): for each pair of non-retired skills with title+when_to_use
  Jaccard ≥ 0.7, keep the one with higher utility (tie → older). Merge the other's steps/pitfalls into it
  (dedupe by lowercase text, respect the caps), add the uses/successes, and retire the other with
  `retired_reason = "merged into <kept_id>"`.

**Tests** (`tests/test_skills.py`): limits validated; duplicate title refused; retrieve ranking and
threshold; retrieve does not mutate; the promotion and retirement thresholds (exact boundary cases);
consolidate merges and retires; corrupt file raises; baseline prior affects transitions.

## E4-2: distillation from a successful job

`distill(job_dir: Path, model: str, chat_fn=chat) -> Optional[Skill]` in skills.py:

- Inputs, all read-only: `job_dir/outcome.json` (goal), `job_dir/run/state.json` (`results_history`,
  `turns`), `job_dir/run/sandbox/plan.md` if present (≤ 2000 chars), and the sorted list of sandbox file
  names (≤ 30). Never send file *contents* other than plan.md.
- Only distill when `outcome.json` has `result == "tests_passed"`; otherwise return None.
- Prompt the model for strict JSON `{"title","when_to_use","steps","pitfalls"}`, with the instruction:
  "Describe a reusable procedure for this *kind* of task, not this specific task; no code; no file
  contents." Call `chat_fn(model, messages, options={"temperature": 0.2, "num_predict": 900})`, parse
  defensively, and validate with the same limits as `add`.
- Reject (return None) if `when_to_use` has fewer than 3 tokens, or if `title` equals the goal text.
- The result is a `Skill` with `status="candidate"` and `source_job_id` set. **It is not added**; the
  caller adds it.

**Tests:** a scripted chat produces a valid candidate; a non-passing job gives None; invalid JSON gives
None; over-limit fields give None; no sandbox file content other than plan.md appears in the prompt
(capture the messages).

## E4-3: worker hook and CLI

- In `cli.py::_execute_queued_outcome`, after the orchestrator run finishes and the job result is known
  (find where `job.result` is set from the run state), add one guarded block:
  - read `state.json` key `skills_used` (a list of ids, possibly absent). If non-empty:
    `SkillLibrary(project_root).record_outcome(ids, success=(result == "tests_passed"))`; else
    `record_baseline(success=...)`.
  - if `job.acceptance_contract.get("distill_skills") is True` and `result == "tests_passed"`:
    `skill = distill(job_dir, job.coding_model)`; if not None, `add` it (catch `SkillError`, e.g. a
    duplicate, and ignore it).
  - **Any exception in this block is caught and recorded in `job.errors` as `"skills: <type>"`**; it must
    never change the job's result.
- CLI `ghost skills list [--status S] [--json]`, `show <id>`, `retire <id> --reason TEXT`,
  `consolidate`, `stats` (baseline, counts per status, mean utility).

**Tests:** the hook records outcome versus baseline (fixture state.json); distill is called only when the
contract flag is set and the job passed; a hook exception does not change the job result; CLI output.
