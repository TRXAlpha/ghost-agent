## Canonical ownership

Ghost retains coding jobs, scheduling, goal/intent state, command budgets, execution policy, verification/promotion, and existing memories. OpenJarvis provides the selected inference engine, optional read-only conversational executor, its conversation database and document index, and Telegram transport. Ghost provides narrow scope/authority checks and receipts at those boundaries. No legacy database migration or second job scheduler was activated.

Local and Telegram histories deliberately remain separate; source-index deletion does not purge copied excerpts from conversation history. Both are explicit OJ03/OJ05 follow-ups, not finished continuity/erasure features.

### OJ06 — 25 September 2026

`ghost_agent/openjarvis_bridge/isolated_execution.py`: a Ghost-owned wrapper around
the pinned OpenJarvis `ContainerRunner` (`openjarvis.sandbox.runner`). It detects
Docker daemon availability, mounts only the sandbox directory read-only, enforces
timeout, and returns structured results. When Docker is unavailable (this host,
as of this date), `run_in_isolation` returns an honest
`available=False / error_type=docker_unavailable` result that callers can fall
back from — it never pretends isolation occurred, and never silently runs
uncontained host commands.

Tests in `tests/test_openjarvis_isolated_execution.py` verify daemon detection
and the unavailable path; the positive isolation acceptance criteria (host
filesystem mount blocked, outbound network refused, timeout enforced, sandbox
artifact preserved) are present as auto-skipped tests that become live once the
Docker daemon runs. Evidence level: contract/unit on the unavailable path; the
live positive path is **not** yet qualified because the Docker daemon is not
running. The existing copied-directory sandbox remains non-isolation; this
wrapper is the forward path but is not wired as the default executor yet.

### OJ08 — 25 September 2026

`ghost_agent/openjarvis_bridge/spend.py`: a durable, atomic inference meter
(`DurableInferenceBudget`) for whole-project model spend. `reserve`/`commit`/
`rollback` are serialized under an exclusive lock and persisted to
`.ghost/openjarvis/spend.json`, so consumption survives job resume/restart and
is shared across parallel calls. Optional caps on calls, input characters, and
usage units refuse over-budget work with `BudgetExceeded` (no silent fallback to
another model). Corrupt meter state fails closed (`CorruptBudgetError`), never
becoming a permissive empty budget.

Wired into `BoundedEngine`/`ask` as an optional `spend=` argument; default
absent keeps existing behavior unchanged. Tests in
`tests/test_openjarvis_spend.py` cover reserve/commit/rollback, cross-instance
persistence, cap refusal, corrupt-state, and engine enforcement. This is the
durable spend half of OJ08; upstream telemetry/traces/router composition and
endpoint-spending qualification remain.

### OJ09 — 25 September 2026

Extended the proactive MVP in `ghost_agent/proactive.py` with the remaining OJ09
opportunity-selection requirements, without rewriting the existing loop:

- **Rejected-idea memory (S07):** `OpportunityStore.find_suppressed()` lets
  `tick()` recognize an identical already-decided idea (`completed`/`rejected`/
  `dismissed`) and return `status=suppressed` instead of re-proposing it.
  `needs_input` is deliberately NOT suppressed (user input is a legitimate defer).
- **Feedback / stop conditions:** `ProactiveEngine.record_feedback()` records the
  worker's evaluated outcome (tests_passed/tests_failed/error) onto the
  opportunity and marks it completed/rejected so it is suppressed on the next tick.
- **Bounded backlog:** `ProactiveEngine._cap_backlog()` keeps at most
  `max_proposed` non-queued opportunities, evicting the lowest-confidence ones by
  marking them `dismissed` (rejected-idea memory is preserved, never deleted).
- **Goal/resource relationships and ranking** were already present via
  `queue_sandbox_outcome` (GoalStore link) and are preserved.

New tests in `tests/test_proactive.py`: suppression for dismissed/completed/
rejected, non-suppression of needs-input, backlog bounding with dismissed
eviction, and feedback status/outcome validation. Full suite: 823 passed.
